# Project unsafe support updates before nonlinear validation

V70 keeps V69's approved initialization, 3265 existing support parameters, immutable rejection classifier, inference thresholds, 61 fitting-only veto-dependent protection candidates, and protected-example sampling. Earlier full-support candidates made little progress because backtracking shrank whole parameter updates when a few protected scores crossed their margins.

For an unsafe update, V70 computes the protected scores' Jacobian at the previous accepted weights in independent batches of at most sixteen. A small nonnegative dual optimization projects the proposed update onto the resulting local halfspaces. Solver success alone is never trusted: linear residuals are explicitly checked and repaired, with retreat toward the feasible zero step if necessary. The actual nonlinear network is then checked on every protected fitting candidate. Existing backtracking and exact rollback remain the final safeguard. No validation input or label participates in this optimizer operation.

Both fixed profiles use the original dataset and partitions: 2302 training and 618 validation recordings. Every original preservation and positive-family-gain requirement remains mandatory at both inference policies. Only one full validation winner across V66–V70 may access consumed regressions and fresh tests; no runner-up after failure, and full native/runtime parity before deployment.

All four protocols were registered before fitting. Full tests: 2258 passed, 7 skipped, 5 warnings. No new audio was downloaded, and no user upload or saved score was processed. Both profiles completed 100 epochs (native exit 0). No checkpoint qualified, and no weights were exported or deployed.

At epoch 100, the quarter-margin candidate removed 73 false notes in normal mode and 49 in strict mode, including real-piano gains. However, each mode also lost one genuinely labeled note, and pitch-coverage preservation failed on five normal-mode and four strict-mode recordings. The three-quarter-margin candidate removed 14 false notes in normal mode and 10 in strict mode without deleting a labeled genuine candidate, but both policies lost reference pitch coverage on one broken-chord recording. It also lacked the required positive gain in every evaluation family. These are failed candidates, not evidence of a safe overall accuracy improvement.

The optimizer repair improved learning compared with repeated whole-step rollback, but training-decision protection did not guarantee preservation on unseen validation recordings. All release checks remain unchanged. No consumed regression or fresh-test data was opened. Approved V43 weights remain unchanged; the website services were not started.

Detailed per-recording diagnostic JSON is stored as deterministic gzip archives. `diagnostic-archives.json` records compressed and uncompressed SHA-256 values, and every archive was verified against native output. Checkpoints remain local, excluded from Git. Across V66–V70, ten fitting profiles completed 1,000 epochs; none met the full validation release requirements.
